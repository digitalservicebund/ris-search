Key: RISDEV-13164
Type: Sub-task
Summary: "Find legislation"
Status: Ready for develop
Description: Find legislation
Goal: Find legislation by keyword or abbreviation, optionally only the ones in force today.
Only currently valid laws are available on Testphase.
Endpoint: GET /v1/legislation1. Search by keyword
All terms must occur in the document. Put the terms in double quotes to search for an exact phrase.curl -G https://testphase.rechtsinformationen.bund.de/v1/legislation \
  --data-urlencode 'searchTerm=Kakao Schokolade'
2. Filter by abbreviationcurl -G https://testphase.rechtsinformationen.bund.de/v1/legislation \
  --data-urlencode 'abbreviation=KakaoV 2003'
3. Get only one current version per law
A law usually has many versions (expressions), and a plain search returns all of them. mostRelevantOn returns exactly one version per law: the one in force on that date. If none is in force on that date, you get the next upcoming version, or else the most recent one.curl -G https://testphase.rechtsinformationen.bund.de/v1/legislation \
  --data-urlencode 'searchTerm=Kakao' \
  --data-urlencode 'mostRelevantOn=2026-11-10'
What you get back
Each entry in member[].item is one version of a law:curl -sG https://testphase.rechtsinformationen.bund.de/v1/legislation \
  --data-urlencode 'searchTerm=Kakao' \
  | jq '.member[].item | {name, abbreviation, legislationIdentifier, temporalCoverage, legislationLegalForce}'

Field
Meaning
name
Official long title (Amtliche Langüberschrift)
abbreviation
Official abbreviation, or the RIS abbreviation if there is no official one
legislationIdentifier
ELI of this version (expression), e.g. eli/bund/bgbl-1/1975/s1760/1998-01-29/10/deu
exampleOfWork.legislationIdentifier
ELI of the law independent of its versions (work), e.g. eli/bund/bgbl-1/1975/s1760
temporalCoverage
Validity period, e.g. 1998-02-06/.. (open end)
legislationLegalForce
Whether this version is currently in force
encoding[].contentUrl
Links to HTML and XML of this versionPitfalls
dateFrom and dateTo filter by “Ausfertigungsdatum”, not by validity. To filter by validity, use temporalCoverageFrom and temporalCoverageTo or mostRelevantOn.
Results are sorted by relevance. Use sort=-date for newest first, or sort=temporalCoverageFrom.
You can page through at most 10,000 results. To get everything, see Download everything [LINK TO DOWNLOAD EVERYTHING].



Key: RISDEV-13165
Type: Sub-task
Summary: "Get a specific version of a law"
Status: Ready for develop
Description: Get a specific version of a law
Goal: Get the text of a law as it was valid on a given date.
Only currently valid laws are available on Testphase.How versions are identified (ELI)
Every law is identified by a European Legislation Identifier (ELI) [LINK TO STANDARDS]. The ELI has three levels:
Level
Meaning
Example
Work
The law, independent of its versions
eli/bund/bgbl-1/1975/s1760
Expression
One version of the law: date it takes effect, version number, language
eli/bund/bgbl-1/1975/s1760/1998-01-29/10/deu
Manifestation
One file of that version, e.g. the main text
…/1998-01-29/10/deu/1998-01-29/regelungstext-1.xml1. List all versions of a law
Filter by the work ELI. You can find it in any search result under exampleOfWork.legislationIdentifier.curl -sG https://testphase.rechtsinformationen.bund.de/v1/legislation \
  --data-urlencode 'eli=eli/bund/bgbl-1/1975/s1760' \
  --data-urlencode 'sort=temporalCoverageFrom' \
  | jq '.member[].item | {legislationIdentifier, temporalCoverage}'
2. Pick the version valid on a date
Set temporalCoverageFrom and temporalCoverageTo to the same day.curl -sG https://testphase.rechtsinformationen.bund.de/v1/legislation \
  --data-urlencode 'eli=eli/bund/bgbl-1/1975/s1760' \
  --data-urlencode 'temporalCoverageFrom=2020-06-19' \
  --data-urlencode 'temporalCoverageTo=2020-06-19' \
  | jq '.member[].item.legislationIdentifier'
3. Get metadata and table of contents of that versioncurl https://testphase.rechtsinformationen.bund.de/v1/legislation/eli/bund/bgbl-1/1975/s1760/1998-01-29/10/deu

The response contains hasPart (the structure of the law down to single articles) and encoding (the available files).4. Get the full text
Use the links from encoding[].contentUrl instead of building the URL yourself:curl -s https://testphase.rechtsinformationen.bund.de/v1/legislation/eli/bund/bgbl-1/1975/s1760/1998-01-29/10/deu \
  | jq -r '.encoding[] | "\(.encodingFormat)  \(.contentUrl)"'
# HTML
curl https://testphase.rechtsinformationen.bund.de/v1/legislation/eli/bund/bgbl-1/1975/s1760/1998-01-29/10/deu/1998-01-29/regelungstext-1.html
# XML (LegalDocML.de)
curl https://testphase.rechtsinformationen.bund.de/v1/legislation/eli/bund/bgbl-1/1975/s1760/1998-01-29/10/deu/1998-01-29/regelungstext-1.xml
Pitfalls
The date in the manifestation part of the URL can differ from the expression date. Always take the URL from encoding.
regelungstext-1 is the main text. Some laws have further files such as attachments (anlage-…). The ZIP of a manifestation contains all of them, see Choose a format [LINK TO CHOOSE A FORMAT] .



Key: RISDEV-13166
Type: Sub-task
Summary: "Get a single article (§)"
Status: Ready for develop
Description: Get a single article (§)
Goal: Get one article, e.g. "§ 3", instead of the whole law.
Only currently valid laws are available on Testphase.1. Find the version of the law
Get the expression ELI as described in Get a specific version[LINK], for example eli/bund/bgbl-1/1975/s1760/1998-01-29/10/deu.2. Look up the article in hasPart
The metadata of a version lists its structure in hasPart. Each part has a display name (name, e.g. § 3), a technical ID (eId) and its own encoding with links. Parts can be nested (e.g. book → section → article), so search recursively:curl -s https://testphase.rechtsinformationen.bund.de/v1/legislation/eli/bund/bgbl-1/1975/s1760/1998-01-29/10/deu \
  | jq '.. | objects | select(.name? == "§ 3") | {eId, headline, url: .encoding[0].contentUrl}'
3. Get the article as HTMLcurl https://testphase.rechtsinformationen.bund.de/v1/legislation/eli/bund/bgbl-1/1975/s1760/1998-01-29/10/deu/1998-01-29/regelungstext-1/{eId}.html

Replace {eId} with the value from step 2.Pitfalls
Single articles are only available as HTML. For XML, get the complete regelungstext-1.xml and select the element with that eId.
Match on name (§ 3), not on the position in the list. Don't rely on the order of hasPart to follow the numbering of the articles.
Look up the eId again for each version of the law instead of reusing it from another version.



Key: RISDEV-13167
Type: Sub-task
Summary: "Find a court decision"
Status: ToDo
Description: Find a court decision
Goal: Find decisions by file number (Aktenzeichen), ECLI, court, date or keyword, then get the full text.
Endpoint: GET /v1/rechtsprechung1. Search by file numbercurl -G https://testphase.rechtsinformationen.bund.de/v1/rechtsprechung \
  --data-urlencode 'fileNumber=VIII ZR 123/23'
2. Search by ECLIcurl -G https://testphase.rechtsinformationen.bund.de/v1/rechtsprechung \
  --data-urlencode 'ecli=ECLI:DE:BGH:2024:120324UVIIIZR123.23.0'
3. All decisions of a court in a period, newest first
court accepts long and short names (Bundesgerichtshof, BGH) as well as court types (Finanzgericht, FG). dateFrom and dateTo refer to the decision date.curl -G https://testphase.rechtsinformationen.bund.de/v1/rechtsprechung \
  --data-urlencode 'court=BGH' \
  --data-urlencode 'dateFrom=2024-01-01' \
  --data-urlencode 'dateTo=2024-12-31' \
  --data-urlencode 'sort=-date'

To see which court names are valid and how many decisions each court has:curl -G https://testphase.rechtsinformationen.bund.de/v1/rechtsprechung/courts \
  --data-urlencode 'prefix=Bundes'
4. Keyword search, only judgments
typeGroup accepts Urteil, Beschluss and other. Use type for the exact document type (e.g. Versäumnisurteil).curl -G https://testphase.rechtsinformationen.bund.de/v1/rechtsprechung \
  --data-urlencode 'searchTerm=Urlaub Arbeitnehmer' \
  --data-urlencode 'typeGroup=Urteil'
5. Get the decision
Every search result contains a documentNumber. It is the stable ID of a decision.# Metadata and full text as JSON
curl https://testphase.rechtsinformationen.bund.de/v1/rechtsprechung/KVRE461542501
# HTML for display
curl https://testphase.rechtsinformationen.bund.de/v1/rechtsprechung/KVRE461542501.html
# XML (LegalDocML)
curl https://testphase.rechtsinformationen.bund.de/v1/rechtsprechung/KVRE461542501.xml
Pitfalls
Not every decision has an ECLI. Use documentNumber to store or link decisions.
Search results use English field names (documentNumber, fileNumbers, courtName). The single document (/v1/rechtsprechung/{documentNumber}) uses German field names (dokumentNummer, aktenzeichenListe, leitsatz, tenor, gruende).

Type: Sub-task
Summary: "Choose a format"
Status: ToDo
Description: Choose a format
Goal: Pick the right format for your application.
You want to …
Use
Why
list, filter or link documents
JSON
Structured metadata, JSON-LD, links to all other formats
show a document to people
HTML
Ready to render, already structured into headings and paragraphs
process the full structure (analysis, own rendering, LLM pipelines)
XML
Complete document in LegalDocML (case law) or LegalDocML.de (legislation)
get the document with all attachments (images, annexes)
ZIP
XML plus all related files in one downloadAvailable document formats
All document types are available in JSON, HTML, XML, and ZIP.
For legislation, you can retrieve different content depending on the format:
JSON: A specific version of a law
HTML: A complete file or an individual article (§)
XML: A complete file
ZIP: A complete manifestation of a law
Court decisions, literature, and administrative directives are available in all four formats.Case law, literature, administrative directives
Add an extension to the URL of the single document:curl https://testphase.rechtsinformationen.bund.de/v1/rechtsprechung/KVRE461542501        # JSON
curl https://testphase.rechtsinformationen.bund.de/v1/rechtsprechung/KVRE461542501.html   # HTML
curl https://testphase.rechtsinformationen.bund.de/v1/rechtsprechung/KVRE461542501.xml    # XML
curl -O https://testphase.rechtsinformationen.bund.de/v1/rechtsprechung/KVRE461542501.zip # ZIP

The same pattern works for /v1/literature/{documentNumber} and /v1/administrative-directive/{documentNumber}.Legislation
JSON is available per version. HTML and XML are available per file of that version (e.g. regelungstext-1). Take the URLs from encoding[].contentUrl of the JSON response.BASE=https://testphase.rechtsinformationen.bund.de/v1/legislation/eli/bund/bgbl-1/1975/s1760/1998-01-29/10/deu
curl $BASE                                    # JSON: metadata and structure
curl $BASE/1998-01-29/regelungstext-1.html    # HTML
curl $BASE/1998-01-29/regelungstext-1.xml     # XML (LegalDocML.de)
curl -O $BASE/1998-01-29.zip                  # ZIP: all files of this version
Pitfalls
Search endpoints only return JSON. To get HTML or XML, follow the links in encoding or add the extension to the single document URL.
For case law, the JSON of a single document already contains the full text fields (e.g. tenor, gruende). For legislation, the JSON contains metadata and structure, but not the text.
More on the data standards: Standards [LINK].



Key: RISDEV-13163
Type: Sub-task
Summary: "Download everything"
Status: ToDo
Description: Download everything of one document kind
Goal: Get all documents of one kind, e.g. for data analysis, research or training language models.
Endpoint: GET /v1/bulk-zip-linksWhy not page through the search?
Search results are limited to 10,000 per query, and requests are limited to 600 per minute (see Rate Limiting [LINK TO RATE LIMITNG]). For complete datasets, use the bulk ZIP files.1. Get the download linkscurl -s https://testphase.rechtsinformationen.bund.de/v1/bulk-zip-links \
  | jq '.dataSet[] | {name, url: .distribution.contentUrl}'

The response lists one dataset per document kind: legislation, rechtsprechung, literature and administrative-directives.2. Download the ZIPURL=$(curl -s https://testphase.rechtsinformationen.bund.de/v1/bulk-zip-links \
  | jq -r '.dataSet[] | select(.name=="rechtsprechung") | .distribution.contentUrl')
curl -o rechtsprechung.zip "$URL"
What is in the ZIP
A snapshot of all documents of that kind as they were when the snapshot was created: XML plus related files such as attachments.
The files are stored flat.Pitfalls
Snapshots are created at most once every 24 hours. Newer changes are only available through the API, see Stay up to date [LINK TO STAY UP TO DATE SECTION].
contentUrl is null if there is no snapshot for that kind (e.g. because no documents of that kind are published yet). Shortly after documents are deleted, the ZIP is recreated and may not be available for a short time.
The ZIP files are large. Download them once and then use the changelog for updates.



Key: RISDEV-13170
Type: Sub-task
Summary: "Stay up to date"
Status: ToDo
Description: Stay up to date
Goal: Keep a local copy in sync without downloading everything again.
Endpoints: one changelog per document kind
Document kind
Changelog
Legislation
/v1/legislation/changelog
Case law
/v1/rechtsprechung/changelog
Literature
/v1/literature/changelog
Administrative directives
/v1/administrative-directive/changelogRecommended workflow
Download the full dataset once, see Download everything [LINK]. Note the time.
On a regular basis (e.g. daily), request the changes since your last run.
Download each changed document from its contentUrl, and delete each document listed in deleted.Request the changes
from and to are required, in ISO 8601 date-time format with time zone.curl -G https://testphase.rechtsinformationen.bund.de/v1/rechtsprechung/changelog \
  --data-urlencode 'from=2026-11-09T00:00:00Z' \
  --data-urlencode 'to=2026-11-10T00:00:00Z'
What you get back{
  "changed": [
    { "@id": "…", "@type": "…", "contentUrl": "…" }
  ],
  "deleted": [
    { "@id": "…", "@type": "…" }
  ],
  "allChanged": false
}

Field
Meaning
changed
Documents that were added or changed. Get them from contentUrl.
deleted
Documents that were removed. Delete them locally.
allChanged
true if the whole dataset was rebuilt. Download the full dataset again.Pitfalls
Let consecutive time windows overlap a little (e.g. start a few minutes before your last to). Processing a document twice does no harm, missing it does.
Always check allChanged before processing the lists.
A time zone offset like +01:00 must be URL-encoded (%2B01:00). --data-urlencode does this for you. Using UTC (Z) avoids the problem.
